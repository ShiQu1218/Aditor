# Apex Highlighter — 計畫 3：UI／UX 改版（工作室、影片庫、設定）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 依 `2026-10-16-ui-redesign.md` 把現有三頁式介面（影片庫／檢視器／剪輯專案）改為「影片庫＋工作室（檢視器與專案軌合併）＋設定」，視覺為 Outplayed 風格的深色遊戲介面，所有現有功能保留，並補上專案自動儲存、監看資料夾、匯出取消、設定儲存。

**Architecture:** 沿用計畫 2 的分層：`app/src/shared` 與 `app/src/renderer` 內的**純 TypeScript 函式**（版面計算、鍵盤分派、剪輯狀態、專案軌排版）以 vitest 測試；React／Canvas 元件只負責接線與繪製。main process 新增 `settings.ts`、`projects.ts`、匯出取消，皆為可用暫存目錄與假 ffmpeg 測試的純 Node 模組。樣式由 `styles/tokens.css`（design token）與 CSS 檔取代內嵌 style。

**Tech Stack:** Electron 33、electron-vite、React 18、TypeScript、vitest、lucide-react（ISC）、Playwright（`_electron`，僅 Task 18）、既有 chokidar。

**Spec:** `docs/superpowers/specs/2026-10-16-ui-redesign.md`（第 2 版，§9 為評審紀錄）；引擎與快取格式仍以 `2026-10-15-apex-highlighter-design.md` 為準。
**Mock（視覺與互動的驗收基準）：** `docs/design/ui-mock/index.html`，截圖在 `docs/design/ui-mock/screens/`。
**前置：** 計畫 1、2 已完成（app 可建置、既有 vitest 全綠）。

## Review Focus

1. **鍵 × 聚焦區矩陣**：焦點在按鈕／輸入框時 `Enter`、`Delete`、方向鍵、`Space` 不得被全域攔截；`Ctrl+Shift+Z`／`Ctrl+Shift+E` 不得被 `Ctrl+Z`／`Ctrl+E` 吞掉 → Task 3 逐格測試。
2. **300–6000 事件的時間軸**：縮小時不得出現圖示疊成一團；`layoutTimeline` 6000 事件 < 5 ms；縮放／拖曳不卡 → Task 4、5、17。
3. **專案不遺失**：任何時刻關閉程式，專案都能還原；寫檔中途失敗不得毀掉上一版；專案檔損毀時保留 `.bak` → Task 9。
4. **匯出取消**：取消後 ffmpeg 子程序（含子孫程序）確實終止、未完成的輸出檔被刪除、已完成的保留 → Task 14（假 ffmpeg）。
5. **快取遷移**：舊快取、重新分析、手動修正三者互動——`accepted` 的片段在重新分析後保留並標記 `stale`，`suggested`／`skipped` 的 AI 片段被取代 → Task 2。
6. **跨影片專案**：專案模式播放他支影片時，來源軌與側欄正確灰化、返回來源後狀態一致 → Task 10、13。
7. **匯出中編輯鎖定**與抽屜不遮住頂欄／專案軌（1366×768）→ Task 15。
8. **無障礙**：全部功能純鍵盤可完成；對比由測試鎖定 → Task 17。
