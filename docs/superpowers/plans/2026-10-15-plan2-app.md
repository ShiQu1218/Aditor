# Apex Highlighter — 計畫 2：Electron 桌面程式 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立仿 Outplayed 的桌面介面（影片庫 → 檢視器 → 剪輯專案 → 匯出），透過 JSON Lines IPC 使用計畫 1 的分析引擎，並打包成可發佈的 Windows 程式。

**Architecture:** Electron main process 管理引擎子程序、影片庫、分析佇列、ffmpeg 匯出與代理檔；renderer 以 React 呈現三個畫面，時間軸用 Canvas 繪製。所有時間軸、片段、專案編輯、匯出指令組裝都是純 TypeScript 函式，用 vitest 測試；UI 元件只負責接線。

**Tech Stack:** Node 24、Electron（最新穩定版）、electron-vite、React 18、TypeScript、vitest、electron-builder、chokidar。

**Spec:** `docs/superpowers/specs/2026-10-15-apex-highlighter-design.md`
**前置：** 計畫 1 已完成（`engine/` 的 IPC 協定見計畫 1 Task 10，快取文件格式見 spec §4.2）。

## Global Constraints

- 程式碼位於 `app/`；`app/src/main`（main process）、`app/src/preload`、`app/src/renderer`、`app/src/shared`（main 與 renderer 共用的純函式與型別）。
- 測試：`app/src/**/*.test.ts`，執行 `npm --prefix app test`（vitest）。
- 介面語言：繁體中文（字串集中在 `app/src/renderer/i18n/zh-TW.ts`，為日後英文做準備）。
- app data 根目錄：`%APPDATA%\ApexHighlighter\`；子目錄 `cache\`（引擎快取）、`proxy\`、`codecs\`（OpenH264 DLL）、`library.json`、`settings.json`。
- 引擎啟動：開發模式 `engine/.venv/Scripts/python.exe -m apexhl ipc`；打包後 `resources/engine/apexhl/apexhl.exe ipc`。ffmpeg 開發模式用 PATH，打包後 `resources/ffmpeg/`，並以 `APEXHL_FFMPEG`/`APEXHL_FFPROBE` 環境變數傳給引擎。
- 預設值（與 spec 一致）：`before=8`、`after=4`、`gap=20`、`n=3`、`max_len=90`。
- 快捷鍵（spec §6）：`Ctrl+F` 搜尋、`Ctrl+D` 收藏、`Ctrl+←/→` 上／下一個事件、`S` 切換速度（1 → 0.5 → 0.25 → 2 → 1）、`Space` 播放／暫停、`Ctrl+Q` 快速剪輯、`M` 新增事件、`Ctrl+E` 送到專案、`Ctrl+Z/Ctrl+Y` 復原／重做、`Ctrl + + / - / 0` 縮放。
- renderer 不得直接存取 Node API；一律透過 preload 暴露的 `window.api`。
- Commit 訊息結尾加上：`Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`

## Review Focus

1. **影片在分析中被刪除或移動**：預期佇列標記錯誤並繼續下一支，不讓引擎卡住 → Task 2 `queue continues after failure` 測試。
2. **2 小時長片（事件數百個）時間軸縮放與拖曳**：預期不卡頓 → Task 3 `heatmap/hitTest` 以 2000 事件、6000 秒測試耗時 < 5ms。
3. **匯出合輯時來源影片解析度或編碼不同**（例如 Exports 的 H.264 與原始長片的 AV1 混用）：預期自動改用重新編碼並提示 → Task 7 `concat incompatible → reencode` 測試。
4. **使用者在分析完成前就開始手動修正**：預期修正不被分析結果覆蓋 → Task 4 `corrections survive analysis result` 測試（以引擎的 merge 行為為準，前端在收到 result 時以 `derive` 重算而非直接覆蓋本地修正）。
5. **引擎程序當掉**：預期所有進行中的請求以錯誤結束、介面可重試、引擎自動重啟 → Task 1 `engine crash rejects pending and restarts` 測試。
