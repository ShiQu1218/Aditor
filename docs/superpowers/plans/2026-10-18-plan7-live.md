# Apex Highlighter — 計畫 7：即時偵測＋錄影中觀看（第 3 期）

**Goal:** 錄影進行中，Python 引擎從 apexrec 的共享記憶體即時偵測擊殺與對局起訖；玩家切出遊戲時可在 App 內看到當局錄影（邊錄邊播）與即時事件。

**Spec:** `docs/superpowers/specs/2026-10-18-live-recording-design.md` §2.2、§3.3–§3.5、§4.3

已完成的前置：apexrec 共享記憶體（版面見 `recorder/src/shm.rs` 檔頭註解，thumb 已改為 640×360 GRAY8、1 fps）；離線擊殺偵測（`engine/apexhl/analyze.py` 等）；離線對局切分（`engine/apexhl/scene.py`、`matches.py`）；App 錄影服務（`app/src/main/recording/`）。

## 合約 1：live 引擎 CLI（E1 實作、E2 使用）

```
python -m apexhl live --shm <名稱> --profile-dir <templates/icons> [--scene-dir <templates/scene>]
（打包版：apexhl.exe live …）
```

- 讀共享記憶體（`OpenFileMappingW` 唯讀；Python 以 `mmap.mmap(-1, size, tagname=名稱, access=ACCESS_READ)` 開啟），依檔頭取得尺寸。讀取規則照 `shm.rs` 註解（`seq_end` → 複製 → `seq_begin`，相等且非 0 才有效）。輪詢 `latest_seq`，落後超過 16 槽就跳到最新（回報 `skipped`）。
- 時間：`pts`（100 ns tick）/ 1e7 = 秒，0 = 錄影開始。
- stdin 收到 EOF 或一行 `{"cmd":"stop"}` → 收尾（`EventTracker.finish`、`MatchTracker.finish(最後時間)`）並送出最終 `snapshot` 後結束，exit 0。
- stdout 每行一個 JSON（UTF-8）：
  - `{"ev":"ready","engine_version":"…","banner":[w,h],"spec":[w,h],"thumb":[w,h]}`：開啟共享記憶體成功後。
  - `{"ev":"snapshot","t":秒,"events":[Event.to_dict()…],"spectating":[SpecInterval.to_dict()…]}`：事件清單（已經過 `derive`，欄位與快取檔 `events` 相同）有變化時送出，最多每秒一次。
  - `{"ev":"match_start","t":秒,"reason":"…"}`／`{"ev":"match_end","t":秒,"reason":"…"}`：`MatchTracker` 的事件（`t` 可能早於目前時間，因為會回推）。
  - `{"ev":"stats","t":秒,"frames":n,"skipped":n,"torn":n,"lag_s":秒,"cpu_ms_per_frame":x}`：每 5 秒。
  - `{"ev":"error","code":"shm_open_failed|bad_layout|internal","message":"…"}`：致命錯誤後 exit 1。
- 擊殺偵測要與離線結果一致：沿用 `Detector`／`EventTracker`／`derive`。`h_scale` 校準與關鍵字學習在離線版是先掃一遍；live 版改為**邊收邊做**：前 N 秒（依離線版的收集門檻）累積候選，達標後確定 `h_scale`／`Keywords`，再把累積的影格補跑一次（緩衝上限與記憶體上限寫成具名常數，例如保留最近 900 秒的 banner/spec，約 4 fps × 900 s）。學到之前送出的 snapshot 可以是空的或暫定的。
- 對局：每張 thumb（1 fps）→ `SceneDetector.classify` → `MatchTracker.feed`。
- 效能預算（規格 §3.6）：單核 CPU 平均 < 5%（4 fps banner+spec＋1 fps thumb）；記憶體 < 200 MB。
- 測試：(a) 寫一個測試用的共享記憶體寫端（Python 依 `shm.rs` 版面寫，或呼叫 apexrec 的 Rust 測試工具皆可），把黃金錄影 `engine/tests/golden/golden.mp4`（`APEXHL_GOLDEN_VIDEO`）以離線解碼的 banner/spec（與 `decode.py` 相同裁切）＋640×360 thumb 依時間餵進去，比對 live 的最終事件與 `analyze` 離線結果：計入事件的召回差 ≤ 5%、不得有離線沒有的計入事件；(b) 用使用者錄影（`APEXHL_MATCH_DIR`）餵 thumb，對局起訖與 `analyze_matches` 結果一致（±2 秒）；(c) 撕裂／跳槽／寫端消失／stdin EOF 的單元測試。

## 合約 2：App 端（E2 實作）

**主程序**
- `main/recording/live-engine.ts`：apexrec 送 `started`（含 `shm`）後，spawn live 引擎（開發：`engine/.venv/Scripts/python -m apexhl live …`；打包：`resources/engine/apexhl/apexhl.exe live …`，參考 `shared/paths.ts` 的 `engineCommand` 寫一個 `liveEngineCommand`），`os.setPriority(pid, PRIORITY_BELOW_NORMAL)`。當掉 → 依規格 §4.3 重啟（指數退避，錄影不受影響）。錄影停止時送 stop 並等最終 snapshot（逾時 5 秒 kill）。
- 事件寫進 session 目錄 `events.jsonl`（每個 match_start/match_end 一行、snapshot 只保留最新一份寫成 `live.json`，原子寫入）。
- 收尾：輸出 mp4 後，把 `live.json` 轉成該 mp4 的分析快取（格式見 `main/cache-io.ts` 與引擎 `cache.py`；標記 `analysis.source = "live"`，狀態設為讓「完整分析」仍會重新分析的值——查 `needs_reanalysis` 決定），使 `postAnalysis = none` 時 Studio 也有事件；`afterExit`／`perMatch` 照舊排完整分析並覆蓋。
- IPC（`RECORDING_CHANNELS` 附加，guard 輸入）：
  - `recording:getLive` → `{ sessionId, mime, segments: [{seq, pts, dur}], events, spectating, matches: [{start, end|null}] } | null`
  - `recording:readInit(sessionId)` → `Uint8Array`；`recording:readSegment(sessionId, seq)` → `Uint8Array`（只允許目前或剛收尾前的 session，seq 必須在 index 中；不得讀 session 目錄以外的檔案）。
  - 推播 `recording:live`：`{ sessionId, segment?: {seq, pts, dur}, events?, spectating?, match? }`（段落與事件增量）。
  - `mime`：由主程序從 `init.mp4` 解析編碼（`hvcC`／`avcC`／`av1C` → RFC 6381 codecs 字串，例如 `video/mp4; codecs="hvc1.1.6.L150.90, mp4a.40.2"`），寫一個小型 box 解析器並測試。
- `RecordingStatus` 附加 `kills`（本局計入擊殺數）與 `matchIndex`（第幾局，從 1 開始；尚無對局資訊時 null）。

**renderer**
- `RecordingPanel` 加「觀看當局」按鈕（錄影中才可用）→ 開啟新的 `LiveScreen`（不重用 StudioScreen：它假設檔案長度固定；收尾後可從媒體庫照常在 Studio 開啟）。
- `LiveScreen`：`MediaSource`＋`SourceBuffer`（`mode = 'segments'`）依序 append init 與段落，收到 `recording:live` 的新段落就 append（佇列化，等 `updateend`）；保留最近 30 分鐘以外的資料要 `remove()` 以控制記憶體；`video.duration` 跟著增長。控制：播放／暫停、跳到最新、±5 秒、事件清單（點擊跳到事件前 3 秒）、時間軸（事件標記＋對局起訖區段，沿用既有事件圖示與顏色 token）。錄影結束（status 離開 recording）→ 顯示「錄影已結束，已加入媒體庫」與開啟按鈕。
- CSP：`media-src` 加 `blob:`（MSE 需要），更新 `shared/csp.ts` 與其測試。
- 字串進 `i18n/zh-TW.ts`；鍵盤操作與 a11y 沿用既有模式（空白鍵播放、方向鍵、`aria-live` 宣告新擊殺）。
- 測試：box 解析器、IPC guard、段落佇列（假 SourceBuffer）、LiveScreen 互動、收尾後快取轉換、live 引擎重啟。
