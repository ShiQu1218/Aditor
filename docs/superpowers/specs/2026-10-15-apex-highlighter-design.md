# Apex Highlighter — 設計規格

日期：2026-10-15
狀態：待審閱

## 1. 目標

一個類似 Outplayed 的 Windows 桌面剪輯程式。輸入**已錄好的** Apex Legends 遊戲影片，自動標註擊倒／助攻等事件的時間點；使用者可在時間軸上手動剪輯，或讓 AI 自動框出「短時間內多殺」的片段，確認後匯出。

最終會開源，**必須能在低階電腦上順暢執行**。

### 成功標準

- 中文（繁體）介面 1080p 影片，「擊倒」事件召回率 ≥ 95%、精確率 ≥ 95%（時間容許誤差 ±1.5 秒）。
- 在一般筆電（內顯、硬體解碼）上分析速度明顯快於影片實際長度；以使用者的 2 小時原始錄影實測並記錄倍速。
- 操作流程與 Outplayed 的「影片庫 → 檢視器 → 剪輯專案 → 匯出」一致。

### 與 Outplayed 的關鍵差異

Outplayed（Overwolf JS 應用，`Outplayed.exe` 僅為啟動器）的事件來自 Overwolf Game Events Provider，是遊戲執行時的即時事件，**不分析影片畫面**。本專案處理的是現成影片，因此事件必須以電腦視覺從畫面上辨識。

## 2. 已確認的需求決策

| 項目 | 決策 |
|---|---|
| 影片來源 | 使用者自己錄製；先支援繁體中文與英文遊戲介面 |
| 參考樣本 | 繁中、1080p 60fps。已剪輯：`E:\Outplayed\Outplayed\Exports`；原始長片：`E:\Outplayed\Outplayed\Apex Legends` |
| 程式形式 | Electron 桌面應用 + Python 分析引擎 + ffmpeg |
| 偵測方式 | 輕量範本比對（不使用 OCR、不使用 AI 模型）；小型 CNN 列為未來備案 |
| 事件時間基準 | 畫面中央的擊倒／淘汰提示**首次出現**的時間。右上角擊殺計數器會延遲到處決後才增加，**不可作為時間基準** |
| 算殺規則 | 擊倒、助攻（擊倒／消滅）、消滅都計入 N；同一敵人去重；小隊抹殺只標記不計入 |
| AI 自動剪輯 | 只把片段框放上時間軸，由使用者確認／調整後才匯出 |
| 匯出 | 每段各一檔，或串成一支合輯，匯出時選擇 |

## 3. 遊戲畫面觀察（繁中，1080p）

提示出現在畫面中央、準星下方，約 `x=610..1310, y=760..850`，為深色半透明底板上的白字，**整塊置中對齊**（關鍵字水平位置會隨敵人名稱長度改變），停留約 2.5 秒，出現時有放大淡入動畫。

| 第一行 | 第二行 | 意義 | 計入 N |
|---|---|---|---|
| `擊倒 [紅字敵人名] +150 (段位圖示)` | `造成 N 點傷害` | 自己擊倒 | 是 |
| `助攻，擊倒 [敵人名] +100` | — | 助攻擊倒 | 是 |
| `(圖示) 助攻，消滅 [敵人名]` | — | 助攻消滅 | 是 |
| `消滅 [敵人名]`（推測，樣本中尚未出現） | — | 自己消滅 | 是 |
| `小隊抹殺 +100` | `[隊友, 💀 敵人名]` | 整隊消滅 | 否（只標記） |

英文介面對應關鍵字預期為 `KNOCKED DOWN`、`ASSIST`、`ELIMINATED`、`SQUAD WIPE`，待取得樣本後擷取範本。

## 4. 架構

```
┌────────────── Electron 桌面程式 (TypeScript) ──────────────┐
│  影片庫 │ 檢視器（播放器 + 時間軸 + 事件標記）│ 剪輯專案 / 匯出 │
└───────────────┬─────────────────────────────────────────────┘
                │ JSON Lines over stdin/stdout
┌───────────────▼─────────────────────────────────────────────┐
│  Python 分析引擎（PyInstaller 單一 exe；依賴 OpenCV + numpy） │
│   decode → detect → events → autoclip                        │
└───────────────┬─────────────────────────────────────────────┘
                │
        ffmpeg / ffprobe（隨程式附帶）：分析解碼、匯出剪切與串接
```

### 4.1 元件

| 元件 | 職責 | 介面 |
|---|---|---|
| `engine/decode` | 以 ffmpeg 硬體解碼（`-hwaccel auto`，失敗則改用軟體）、`fps=4`、裁切 ROI、轉灰階，輸出 numpy 畫格流 | `iter_frames(path, roi, fps) -> (t, ndarray)` |
| `engine/detect` | 二值化白字；以 `cv2.matchTemplate` 在 ROI 內滑動比對關鍵字範本；回傳單格判定 | `detect(frame) -> FrameHit \| None`（類型、分數、x 位置、名字指紋） |
| `engine/events` | 狀態機把連續命中合併為事件、去重同一敵人 | `build_events(hits) -> list[Event]` |
| `engine/autoclip` | 「X 秒內 ≥ N 殺」滑動視窗分群、產生片段、合併重疊 | `auto_clips(events, window, n, before, after) -> list[Clip]` |
| `engine/ipc` | 接收指令（analyze / cancel / autoclip），回報進度與結果 | JSON Lines |
| `templates/<lang>/` | `profile.json`（ROI、關鍵字清單、門檻、事件類型對照）＋關鍵字 PNG | 外部檔案，改版時只換範本不需重新打包 |
| `app/` | 影片庫、檢視器、剪輯專案、匯出、設定 | Electron main/renderer |
| `tools/` | 範本擷取、準確率評估、Outplayed 正確答案匯出 | CLI |

### 4.2 資料格式

每支影片旁產生快取 `<影片名>.apexhl.json`：

```json
{
  "version": 1,
  "video": { "path": "...", "duration": 6012.4, "width": 1920, "height": 1080, "size": 0, "mtime": 0 },
  "profile": "zh-TW",
  "analysis": { "status": "done", "progress_t": 6012.4, "engine_version": "0.1.0" },
  "events": [
    { "id": "e1", "t": 812.25, "type": "knock", "score": 0.91, "damage_line": true, "name_sig": "base64...", "source": "auto" }
  ],
  "clips": [
    { "id": "c1", "start": 804.0, "end": 836.5, "origin": "ai", "event_ids": ["e1", "e2", "e3"] }
  ]
}
```

- `type`：`knock` | `assist_knock` | `assist_elim` | `elim` | `squad_wipe`
- `source`：`auto`（偵測）| `manual`（使用者新增）；使用者刪除的自動事件記為 `"deleted": true` 保留，以供準確率評估。
- 若影片 `size`/`mtime` 改變則快取失效。

## 5. 偵測演算法

1. **ROI**：以 1080p 座標定義於 `profile.json`，其他解析度依高度比例換算；非 16:9 時警告但繼續。
2. **前處理**：灰階 → 保留接近白色的像素（閾值定義於 profile），消除背景干擾。
3. **關鍵字比對**：依序比對 `小隊抹殺` → `助攻` → `擊倒` → `消滅`（「助攻」優先，避免「助攻，擊倒」被判成自己擊倒）。「助攻」命中後，再於其右側判斷是「擊倒」或「消滅」。第二行 `造成` 命中時加分並標記 `damage_line`。
4. **事件追蹤**：至少連續 2 格命中才成立（排除淡入動畫的變形畫格）；時間取首次命中那一格。提示消失 ≥ 0.5 秒後再出現，或名字指紋明顯改變，視為新事件。
5. **名字指紋**：第一行關鍵字右側區塊的二值縮圖。
6. **去重**：30 秒內名字指紋相似（相關係數高於門檻）的計數事件視為同一敵人，只計一次（例如「助攻，擊倒 X」後接「助攻，消滅 X」、或「擊倒 X」後接「消滅 X」）。被去重的事件仍顯示在時間軸上，但不計入 N。
7. **自動剪輯**：對計數事件做滑動視窗，凡 `window` 秒內 ≥ `n` 個即成群；片段為 `[首殺 − before, 末殺 + after]`，重疊合併，並限制在影片範圍內。預設 `window=20, n=3, before=8, after=4`。

## 6. 使用介面與流程（仿 Outplayed）

### 6.1 影片庫
- 卡片格狀清單：縮圖、日期、長度、擊倒／助攻數徽章、分析狀態（未分析／分析中 xx%／完成／錯誤）。
- 匯入：拖放檔案、選擇資料夾；可設定監看資料夾，新影片自動排入分析佇列（一次只分析一支）。
- 搜尋 `Ctrl+F`、收藏 `Ctrl+D`、依事件類型篩選。

### 6.2 檢視器
- 播放器（Chromium `<video>`）＋ Canvas 時間軸：事件標記（依類型使用不同顏色／圖示）、熱度條、片段框、縮放 `Ctrl + + / - / 0`。
- 點擊標記或右側事件清單 → 跳到事件前 `before` 秒播放；`Ctrl+←/→` 上一個／下一個事件；`S` 切換播放速度；`Space` 播放／暫停。
- 事件類型篩選勾選框。
- 快速剪輯 `Ctrl+Q`：以播放頭為事件點建立片段；拖曳片段框兩端調整長度。
- 勾選事件 → 「建立合輯」：每個事件依前後秒數變成片段，重疊合併。
- 「AI 自動剪輯」：對話框設定 `window`、`n`、`before`、`after`，結果以「AI」標籤片段框加入時間軸，可調整或刪除。
- 手動修正：刪除誤判事件、`M` 於播放頭新增事件（可選類型）。修正寫回快取。

### 6.3 剪輯專案
- `Ctrl+E` 把選取的片段送進專案；專案時間軸支援分割、刪除、複製、拖曳排序、微調起訖點、`Ctrl+Z / Ctrl+Y`。
- 專案存成 `.apexproj.json`（片段來源影片路徑＋起訖時間）。

### 6.4 匯出
- 模式：每段各一檔／串成一支合輯。
- 品質：「快速無損」（`-c copy`，從關鍵影格切，可能多出 1–2 秒）／「精準重新編碼」（依序嘗試 NVENC、QSV、AMF，皆不可用時使用 libx264）。
- 匯出前檢查磁碟空間；失敗時保留 ffmpeg stderr 供回報。

### 6.5 第一版不做
上傳分享、浮水印、畫面裁切、音軌管理、轉場特效、遊戲內錄影、OCR、英文範本的實際擷取（格式與工具先備妥）。

## 7. 錯誤處理

| 狀況 | 處理 |
|---|---|
| 硬體解碼失敗 | 自動改用軟體解碼並在介面提示 |
| ffprobe 無法讀取／檔案損壞 | 影片庫卡片標紅並顯示原因，不中斷佇列 |
| 解析度非 16:9 | 警告「準確度可能下降」，仍執行 |
| 分析中取消或程式關閉 | 每 30 秒寫入 `progress_t`，下次從該處接續 |
| 引擎程序異常結束 | Electron 偵測到程序結束，標記錯誤並允許重試 |
| 匯出磁碟空間不足／ffmpeg 失敗 | 事前檢查；失敗時顯示 stderr 摘要 |
| 範本檔遺失或 profile 格式錯誤 | 啟動時驗證，顯示明確錯誤 |

## 8. 測試

- **引擎單元測試（pytest）**：以從使用者影片擷取的提示列 PNG 作為測試資料，正例（各事件類型）與反例（跑圖、物品欄、死亡畫面、爆炸火光）；事件追蹤、去重、自動剪輯視窗、片段合併各自測試。
- **前端單元測試（vitest）**：時間軸座標換算、片段拖曳／合併、快捷鍵行為、專案時間軸編輯與復原。
- **準確率評估**（`tools/evaluate`）：偵測結果與正確答案比對（±1.5 秒），輸出各類事件的召回率／精確率與漏抓、誤抓清單。
  - 正確答案優先從 Outplayed 的 IndexedDB（`%LOCALAPPDATA%\Overwolf\CefBrowserCache\Default\IndexedDB\overwolf-extension_cghphpbjeabdkomiphingnegihoigeggcfphdofo_0.indexeddb.leveldb`，已確認含 `knockdown`／`assist`／`killCount` 記錄）解析；若無法解析，改以程式的手動修正功能人工標註一支長片。
- **速度基準**（`tools/benchmark`）：同一支長片分別以硬體解碼與強制軟體解碼執行，記錄倍速。

## 9. 專案結構

```
apex-highlighter/
  app/          Electron + TypeScript
  engine/       Python：decode/ detect/ events/ autoclip/ ipc/
  templates/    zh-TW/ en/
  tools/        extract_templates, evaluate, benchmark, outplayed_truth
  docs/
```
