## 追加發現與修正

8. **WGC 自動改錄螢幕後，切換到其他程式仍會被錄下**
   - 位置：`recorder/src/capture/mod.rs` 的 `ActiveCapture::new`、`CallbackState::frame` 與黑畫面 fallback；對照 `capture/dda.rs` 的 `Output::visible`。
   - 用途：視窗連續黑畫面時，自動改用 `CreateForMonitor` 擷取整個螢幕。
   - 問題：monitor fallback 每張畫面直接交給編碼器，沒有確認前景視窗仍屬於遊戲。使用者 Alt+Tab 到瀏覽器或通訊軟體時，其他程式的畫面也會錄入；DDA 已有的非前景黑畫面保護未套用到此路徑。
   - 已實作：monitor fallback 沿用 DDA 的前景 PID／最小化判斷與 GPU 黑畫面；非遊戲前景時輸出黑畫面，保留時間戳與隱藏／恢復通知，並處理擷取重建和尺寸變更。
   - 不修的後果：錄影可能包含使用者沒有預期要錄下的私人畫面。
   - 證據限制：程式路徑已確認，未操作使用者遊戲、切換視窗或實際錄影重現。

9. **同一個回合尾端擊殺會進入兩局的多殺判定**
   - 位置：`engine/aditor/valorant_rounds.py:round_highlights`。
   - 用途：容許擊殺資訊比比分變更晚出現 3 秒，再產生該局的多殺／王牌事件。
   - 問題：前一局範圍延伸到 `end + ROUND_TAIL`，下一局仍從相同的 `end` 開始，形成重疊。兩局為 `[0, 100]` 與 `[100, 200]`，擊殺時間為 99、101、150 秒時，101 秒那次擊殺同時用於兩局，第二局只有一次實際新擊殺卻得到多殺。
   - 已實作：每個擊殺 ID 只歸屬一局，較早回合優先取得尾端延遲擊殺，保留 3 秒容錯；新增相鄰局、非相鄰局與尾端上界測試。
   - 不修的後果：下一局會得到錯誤的多殺／王牌標記與精華建議。
   - 修正前證據：已用真實 `Event`、`Round` 與 `round_highlights` 函式斷言重現，輸出兩筆 `multikill`，時間分別為 101 與 150 秒、各計兩次擊殺；修正後只保留前一局的多殺。
