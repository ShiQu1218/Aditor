# Valorant 延遲與玩家標記修正（valorant-feed@8）

延續 [第一階段追蹤測試](valorant-visual-tracking.md)，本次只處理剩餘延遲與玩家身分誤判，不使用音訊，也不寫入使用者影片分析快取。

## 0.8 秒延遲的原因

Radiant Visual Guide 在 170.75 秒已有一次擊殺 palkia。擊殺列最後於 174.5 秒被觀察到，之後畫面轉場、擊殺列消失；177.2 秒的新片段再次擊殺同名對手。

在 177.25 秒的取樣畫面中，偵測器已能正確辨識新的玩家擊殺列，並非黃色門檻太晚通過。然而舊追蹤只依首次出現後 7 秒到期，沒有因擊殺列持續消失而結束。因此新列被接到 170.75 秒的舊事件；直到 178.0 秒舊追蹤到期，才建立新事件。

修正後，連續觀察到整個擊殺列區域沒有候選超過 1.5 秒，會結束舊追蹤。177.25 秒的新列立即建立新事件，與目視真值 177.2 秒相差 +0.05 秒。不是固定扣秒，也沒有提高 FPS。

只有單一列暫時看不清、其他列仍可見時，會保留既有追蹤，避免快速連殺滑動時重複計數。單純兩次呼叫間隔較長、沒有中間空畫面證據，也不當作持續消失。

## 玩家身分誤判的原因

LFT 68.75 秒出現的是 Killjoy 擊殺 Clove，並非錄影玩家的擊殺。71.25 秒，Killjoy 的黃色衣服與背景接成 22×34 像素的黃色區塊，符合舊的頭像高度判斷；淡黃背景又提供足夠的「外框」像素。這次錯誤確認會回溯到 68.75 秒，產生誤判。

修正包含：

- 限制擊殺標記位於擊殺者一側，避免受害者頭像或武器附近的黃色區塊被當成自己的頭像。
- 黃色區塊若較稀疏，必須另有飽和黃色外框，或具有突出箭頭尖端的形狀。單純直條衣服加上淡黃背景不足以確認。
- 淡黃色箭頭亦可作為證據，但要求尖端突出於上下兩翼，並同時有列邊緣、黃色外框與己方底色。保留原先飽和箭頭的判斷路徑。

這排除了該 Killjoy 誤判，同時保留 LFT 的真正玩家擊殺與低解析度賽事畫面的稀疏黃色箭頭。弱候選仍不能獨立產生事件。
