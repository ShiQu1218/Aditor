## 娛樂模式

原本的 Apex 偵測依賴積分箭頭、人物／握手圖示；團隊死鬥的「消滅了」「助攻，消滅了」只有文字，沒有傷害列。
新增的 `MixtapeDetector` 使用繁體中文關鍵字影像、置中的提示版面及名稱筆畫，不依賴傷害。
助攻前綴優先於其中的消滅關鍵字，避免把助攻判為擊殺。

`kill` 表示直接擊殺，`assist_elim` 表示助攻。名稱指紋用來區分連續提示，
不寫入這兩類事件的跨事件去重欄位，因此同一位敵人重生後能再次計入。
提示短暫失去名稱筆畫時保留延續訊號；文字不淡出而直接換人時，使用穩定的新名稱切分事件。

左下角擷取範圍從 `(60,1028,480,40)` 擴充為 `(60,950,480,118)`，
保留觀戰提示並加入玩家名稱。實際傳給錄影器的所有長寬比聯集為 `(60,950,480,122)`；
共享記憶體協定不變，尺寸仍由設定檔協商。
比對受害者與當前左下角名稱，相同則排除；比對容許顏色、字級與英文字母大小寫造成的筆畫差異。
名稱比對使用完整文字外緣；尾端喇叭圖示另外定位，不把名稱內部空白或受害者子字串當成完整玩家名稱。
觀戰文字偵測仍限制在原本的 1028–1068 提示列，不會掃描新增的玩家名稱區域。
沒有可用的玩家名稱時不產生新的文字擊殺事件。

設定檔版本改為 `icons@2`，讓舊分析快取重新分析，保留既有使用者編輯的合併流程。

其他娛樂玩法、其他語言、名稱高度相似或 HUD 被遮住的情境，仍需額外影片驗證。

## 控制模式右上角擊殺紀錄

新增 `ControlFeed`，只在辨識到控制模式據點列後啟用，看到大廳或新開場即解除。
核對右上角青色攻擊者的完整字形與左下角玩家名稱，並要求武器及受害者文字；
核對成功後於此控制對局保留本人名稱，避免死亡或 HUD 暫時遮擋造成失去追蹤。

## 灰階控制模式辨識最終版（icons@8，2026-10-30）

`icons@8` 移除控制模式的顏色規則（青色、藍色、暗粉色備援），改用灰階字形與列結構：
以 HUD 本人名稱在擊殺欄的筆畫遮罩上做多尺度比對，再檢查武器形狀與受害者字形。
