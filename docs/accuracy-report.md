## 4. 差異案例逐筆開圖檢驗

針對表定評估中出現的 3 筆「表定誤抓（false positive）」，我們擷取了該時間點的橫幅圖像並逐一開圖檢視：

### 4.1 Project 60 @ 10.50s (預測 knock, score=0.894, dmg=True)
- **畫面事實**：畫面中央於 10.50 秒清晰顯示「`擊倒 GUUUUUUUN +150`」及第二行「`造成 108 點傷害`」。
- **Outplayed 真值**：在 11.17 秒記錄為 `kill Kill`（因該名敵人隨即被消滅）。
- **判定**：**真擊倒**。引擎正確捕捉到了畫面上的擊倒提示；Outplayed 因遊戲邏輯將其合併記為消滅。

### 4.2 Project 64 @ 5.75s (預測 knock, score=0.977, dmg=True)
- **畫面事實**：畫面中央於 5.75 秒清晰顯示「`擊倒 探路者4582 +150`」及第二行「`造成 45 點傷害`」。
- **Outplayed 真值**：在 6.47 秒記錄為 `kill Kill`。
- **判定**：**真擊倒**。畫面為 100% 擊倒橫幅，無誤抓。

### 4.3 Project 66 @ 28.00s (預測 knock, score=0.881, dmg=True)
- **畫面事實**：畫面中央於 28.00 秒清晰顯示「`擊倒 你也不必牽強再說愛我 +150`」及第二行「`造成 217 點傷害`」。
- **Outplayed 真值**：Outplayed 在該剪輯檔中僅記錄了第一筆擊倒（18.01s），遺漏第二筆。
- **判定**：**真擊倒**。為 Outplayed 原始事件記錄不完整，引擎正確識別第二個擊倒。

**結論：短片測試集中，擊倒之真召回率為 100%，真精確率為 100%。**

## 6. 速度基準測試（`tools/benchmark.py`）

對長片 `Apex Legends_10-13-2026_18-26-50-167.mp4` 前 600 秒進行純解碼＋逐格偵測迴圈基準測試：

| 解碼模式 | 影片時長 | 實際耗時 | 分析倍速 | 處理格數 (4 fps) | 啟動延遲 |
|---|---|---|---|---|---|
| **硬體解碼 (`-hwaccel auto`)** | 600.2 秒 | 134.7 秒 | **4.46x** | 2,401 格 | 0.2 秒 |
| **軟體解碼 (強制 CPU dav1d)** | 600.2 秒 | 132.0 秒 | **4.55x** | 2,401 格 | 0.1 秒 |

### 分析結論
1. **倍速達標**：在 1080p60 AV1 格式下，分析倍速達 4.5x 即時（一場 20 分鐘的對局僅需約 4.4 分鐘即可分析完成）。
2. **軟硬體解碼無顯著差異**：硬體解碼將畫格留在 GPU，但後續的裁切拼接與 OpenCV 處理需透過 pipe 回傳 host 記憶體；dav1d 多執行緒軟體解碼直接在 CPU 上產生 BGR 畫格，效能甚至微幅領先。在低階電腦（無專用 AV1 硬體解碼器）上，軟體解碼表現完全符合產品需求。
