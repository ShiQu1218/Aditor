# Aditor v0.4.4

## 新增與改善

- **錯誤回報隨機安裝識別碼（Install ID）**：啟用錯誤回報時，於本機應用程式資料夾產生隨機 UUID v4 作為 `user.id`，用於統計各問題影響的安裝數量。此識別碼不衍生自硬體、帳號或路徑，且同樣不收集 IP 位址；未啟用時不會建立，關閉錯誤回報時會立即刪除。既有已開啟錯誤回報的使用者升級後亦適用此機制，可隨時至「設定」關閉錯誤回報以刪除識別碼。
- **子程序啟動失敗提示與診斷**：分析引擎、錄影器或即時辨識執行檔缺失或無法啟動時，顯示多語系說明提示（如防毒隔離、權限不足或安裝不完整），並在診斷資訊保留安全的系統錯誤碼（`spawn_errno`）。
- **遙測分組與診斷資訊強化**：
  - 子程序診斷改以穩定的英文分類與正規化標題分組，不再因動態計數器、階段數值或介面語言拆成多個重複問題；音訊 FIFO／AAC 配置錯誤與時間戳缺口依各自根因分開歸類。
  - 忽略外部強制終止（如系統關機或工作管理員結束，exit code `0x40010004`、`0xC000013A`）造成的非崩潰結束。
  - FFmpeg 解碼失敗時附帶經路徑去識別化的完整最後數行 `stderr` 輸出；區分錄影索引建立失敗與讀回失敗的診斷訊息；即時辨識引擎異常結束時附帶結束代碼與 `stderr` 摘要。

## 修正

- **補幀期間持續處理排隊音訊**：修正追補固定影格率（CFR）影格時，編碼執行緒在內部迴圈連續補幀而未先排空音訊佇列，導致已排隊的聲音被靜音覆蓋的問題。
- **錄影暫時卡頓後的有界降級與恢復**：
  - 超過 2 秒的視訊缺口改以稀疏補幀降級，保留 2 秒關鍵影格邊界與原始 PTS 時間軸，不再逐一重編所有舊時槽；合成 7 秒視訊缺口測試中，編碼張數由 639 張降至 17 張，追補與收尾時間中位數由 872.9 毫秒降至 30.5 毫秒。
  - 超過 5 秒的音訊缺口改以每次最多 0.5 秒分批補齊靜音並與視訊交錯處理，修正暫時卡頓後因音訊缺口超過 5 秒而直接中止整段錄影的問題（合成 7 秒音訊缺口測試由 0/9 成功提升至 9/9 完整收尾）。
  - 封裝（mux）佇列滿載等待上限由 2 秒提高至 10 秒，並為壓縮佇列與未封段封包加上 64 MiB 記憶體上限；逾時時說明磁碟過慢或不可用，並保留已完成分段。
  - 編碼器連續 5 秒無輸出時發送單次多語系警告，恢復輸出後重設；連續停滯達 60 秒才升級為編碼失敗。
- **錄影期間音訊裝置失效重連**：音訊裝置開啟失敗或錄影中途失效時，保留音訊時間軸並以靜音填補，同時約每秒重試原裝置（選用預設裝置時重新解析目前預設裝置，指定特定麥克風時不擅自切換至其他裝置）。

## 已知限制

- 錄影卡頓追補數據來自本機合成缺口測試，不代表實際遊戲 FPS 改善，亦不代表所有硬體或真實慢速磁碟的表現。
- 原生驅動、編碼器或磁碟 I/O 若永久卡死，仍可能使停止錄影需要等待；卡頓期間若超出音訊佇列容量，已丟棄的原始音訊僅能以靜音填補；中斷時僅保證保留已完成的分段，最後未完成的分段不保證完整。
- 解碼與錄影索引變更僅新增診斷資訊，尚未直接修復對應的底層個案根因。
- Windows 執行檔未進行程式碼簽章。

## 更新方式

- **0.2.2 至 0.4.3 安裝版**可透過自動更新升級。
- **0.2.0／0.2.1 安裝版**請手動下載並執行 `Aditor-Setup-0.4.4.exe`。

## New and improved

- **Random install ID for telemetry**: when error reporting is enabled, the app stores a random UUID v4 as `user.id` in the local app data directory so issues show how many installs they affect. The ID is not derived from hardware, account or path data, and IP addresses are still never collected; it is never created while telemetry is disabled and is deleted immediately on opt-out. Existing users who opted in on earlier versions are also covered by this change and can disable error reporting in Settings at any time to delete the ID.
- **Spawn failure explanations and diagnostics**: when the analysis engine, recorder or live-detection executable is missing or cannot start, the app shows localized guidance (such as antivirus quarantine, permissions or an incomplete install) and preserves a safe `spawn_errno` in diagnostics.
- **Better telemetry grouping and fault diagnostics**:
  - Child diagnostics now use stable English categories and normalized titles for Sentry grouping instead of splitting one fault across issues by counters, pipeline stages or UI language; audio FIFO/AAC allocation errors and audio timestamp gaps are grouped by their respective root causes.
  - Exits caused by external termination (`0x40010004`, `0xC000013A`) are no longer reported as crashes.
  - FFmpeg decode failures now include redacted complete trailing lines from `stderr`; recording index creation and read-back failures report distinct messages; live-engine crash diagnostics include the exit code and `stderr` tail.

## Fixes

- **Drain queued audio during CFR catch-up**: the encoder worker now drains queued audio between CFR catch-up frames instead of filling the whole frame gap first and overwriting queued audio with silence.
- **Bounded recovery after temporary recording stalls**:
  - Video gaps longer than 2 seconds now degrade to sparse catch-up frames while preserving 2-second keyframe boundaries and the original PTS timeline instead of re-encoding every missed slot; in a synthetic 7-second video gap benchmark, encoded catch-up frames dropped from 639 to 17 and median catch-up/finalization time dropped from 872.9 ms to 30.5 ms.
  - Audio gaps longer than 5 seconds are now filled in chunks of up to 0.5 seconds interleaved with video instead of aborting the recording immediately (improving synthetic 7-second audio gap completion from 0/9 to 9/9).
  - The mux queue full wait timeout is raised from 2 seconds to 10 seconds with 64 MiB payload caps on queued and pending packets; timeouts explain slow or unavailable disks and preserve completed segments.
  - A 5-second encoder output stall emits a single localized warning per stall episode and escalates to an encoding failure only after 60 seconds without output.
- **Audio device reconnection during recording**: when an audio device fails to open or drops out mid-recording, the recorder preserves the audio timeline, fills silence, and retries the original source roughly once per second (re-resolving the current default device when set to default, without switching away from an explicitly chosen microphone).

## Known limitations

- Stall-recovery figures come from local synthetic gap benchmarks and do not represent real game FPS improvements or every GPU/disk configuration.
- Permanently hung native driver, encoder or disk I/O calls can still block shutdown; raw audio dropped after exceeding the audio queue capacity can only be replaced with silence; only completed segments are guaranteed to be preserved when a recording aborts.
- The decode and recording-index diagnostic changes only improve fault visibility and do not fix the underlying root causes.
- Windows executables are not code signed.

## How to update

- **0.2.2 through 0.4.3 installs** can upgrade through auto-update.
- **0.2.0/0.2.1 installs** need to download and run `Aditor-Setup-0.4.4.exe` manually.
- **Portable builds**: download `Aditor-0.4.4-Portable.exe` to update manually.
