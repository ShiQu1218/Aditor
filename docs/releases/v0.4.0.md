# Aditor v0.4.0

## 重點

- **錄影更不影響遊戲**：錄影時遊戲的 1% low 最多提升約 9%（視窗擷取、SDR），錄影對 1% low 的影響已降到量不出來。詳見下方「效能」。
- **遊戲中不再跑背景分析**：Apex Legends 或 VALORANT 執行時，背景分析會暫停，等遊戲結束才開始。遊戲中跑背景分析原本會讓 1% low 下降約 16.5%、0.1% low 下降約 23.6%。
- **分析引擎改用 Rust 重寫**：完整分析快約 20%，既有的分析快取可直接沿用。
- **系統音訊不再錄進 Aditor 自己的聲音**：錄影中打開 Aditor 預覽時，預覽的聲音不會再被錄進去、越疊越大聲。

## 效能

以下數字來自單一台電腦（RTX 5080、4K 240 Hz 螢幕、Windows 11）上的模擬遊戲負載，錄影設定為 HEVC 1080p60 NVENC。實際遊戲的 FPS 會因電腦與畫面而不同，僅供參考。

**錄影時的遊戲 FPS（與 0.3.6 相比）**

| 擷取方式 | 平均 FPS | 1% low | 0.1% low |
| --- | ---: | ---: | ---: |
| 視窗擷取（WGC），SDR | +1.4% | **+9.2%** | +9.5% |
| 視窗擷取（WGC），HDR | +0.8% | **+7.6%** | +2.6% |
| 螢幕擷取（DDA），SDR | −0.5% | **+3.6%** | +2.8% |
| 螢幕擷取（DDA），HDR | +0.3% | **+4.0%** | +5.2% |

- 視窗擷取（SDR）錄影對 1% low 的影響從 −6.5% 降到量不出來。
- 0.1% low 每次量測的差異較大，百分比只能參考。
- 分析引擎：四段實際錄影的完整分析從 50.1–59.6 秒縮短到 39.1–47.9 秒，結果與舊版相同。

## 新增與改善

- **錄影 GPU 成本降低**：SDR 螢幕改用較省的畫面格式；NVIDIA 顯示卡直接以 NV12 送入編碼器；HDR 在錄影解析度做色調對應；螢幕擷取的游標改由 GPU 繪製。
- **分析引擎**：改為 Rust 程式，不再打包 Python。引擎結束時，它啟動的 FFmpeg 也會一併結束。

## 修正

**錄影**
- **逐局錄影變成一整段**：螢幕擷取（DDA）在對局之間切出遊戲時，偵測畫面會正確變黑，對局能正常切開。切回遊戲的瞬間，偵測畫面也不會再混入桌面內容。
- **視窗擷取還原後偵測停擺**：遊戲從最小化還原但沒有取得焦點時，即時偵測會正常恢復，也不會再誤報視窗遺失。
- **VALORANT 錄影被當成 Apex**：整段收尾或從中斷恢復時，會保留錄影的遊戲類型。
- **OBS 逐局收尾**：即時事件轉換失敗時，仍會排入分析並列出輸出檔。
- **即時偵測未正常結束**：會保留對局影片，不會遺失片段。
- **部分顯示卡錄影中斷**：影像處理器無法直接讀取畫面時改用複製，不再中斷錄影。
- **游標邊緣過暗**：修正游標陰影與邊緣被畫得太暗。

**分析**
- **大逃殺被誤判為控制模式**：修正大逃殺錄影長時間被誤判、導致擊殺橫幅全部遺漏的問題。
- **分析佇列與工作室卡住**：遊戲偵測失敗、分析被取消或失敗時，佇列會繼續處理，工作室也能重新載入或重試。
- **重新分析遺失剪輯**：取消、切換快取位置或遊戲中途啟動時，已接受的 AI 片段不會再遺失。
- **分析引擎當掉後無法再分析**：引擎內部錯誤時會回報錯誤，不再一直顯示忙碌。

**監看資料夾**
- **複製中的檔案匯入失敗**：會等檔案寫完、解除鎖定後再匯入；權限設定只允許讀取的檔案也能匯入。
- 監看資料夾的變更無法儲存時會顯示提示。

**匯出**
- **誤跳 OpenH264 下載提示**：開啟匯出時，會等編碼器偵測完成再判斷是否需要 OpenH264。
- **多來源誤判可快速匯出**：有來源無法讀取規格時，不再顯示可免重新編碼。
- 多段匯出的進度依各段長度計算，更平順。

**資料安全**
- 設定檔損壞時保留原檔，隱私選項（診斷資料、自動錄影）維持關閉。
- 媒體庫檔案無法讀取或備份時，不會被覆寫。
- 還有未完成的錄影時，不能變更儲存位置，避免錄影遺失。

**其他**
- 即時畫面保持開啟時，會跟上新開始的錄影；切換影片後播放鍵狀態正確。
- 修正系統列圖示遺失、自動更新記錄造成的錯誤。

## Highlights

- **Recording costs the game less**: while recording, the game's 1% low improves by up to about 9% (window capture, SDR), and recording no longer has a measurable effect on the 1% low. See "Performance" below.
- **No background analysis while you play**: background analysis pauses while Apex Legends or VALORANT is running and starts after the game exits. Running it during play used to lower the 1% low by about 16.5% and the 0.1% low by about 23.6%.
- **Analysis engine rewritten in Rust**: full analysis is about 20% faster, and existing analysis caches keep working.
- **System audio no longer records Aditor itself**: opening the Aditor preview while recording no longer feeds its sound back into the recording and makes it louder and louder.

## Performance

These numbers come from a synthetic game load on a single PC (RTX 5080, 4K 240 Hz display, Windows 11), recording HEVC 1080p60 with NVENC. Real games vary by PC and scene, so treat them as a guide.

**Game FPS while recording (compared with 0.3.6)**

| Capture | Average FPS | 1% low | 0.1% low |
| --- | ---: | ---: | ---: |
| Window capture (WGC), SDR | +1.4% | **+9.2%** | +9.5% |
| Window capture (WGC), HDR | +0.8% | **+7.6%** | +2.6% |
| Screen capture (DDA), SDR | −0.5% | **+3.6%** | +2.8% |
| Screen capture (DDA), HDR | +0.3% | **+4.0%** | +5.2% |

- With window capture (SDR), recording's effect on the 1% low dropped from −6.5% to no measurable difference.
- The 0.1% low varies a lot between runs, so its percentages are only indicative.
- Analysis engine: full analysis of four real recordings went from 50.1–59.6 s to 39.1–47.9 s, with the same results as before.

## New and improved

- **Lower recording GPU cost**: SDR displays use a cheaper frame format, NVIDIA GPUs feed the encoder NV12 directly, HDR is tone-mapped at the recording size, and screen capture draws the cursor on the GPU.
- **Analysis engine**: now a Rust program instead of packaged Python. FFmpeg processes it starts now exit with it.

## Fixes

**Recording**
- **Per-match recording saved as one file**: with screen capture (DDA), switching away from the game between matches blanks the detection frames again, so matches split correctly. Detection frames no longer pick up desktop content right after you switch back.
- **Detection stalled after restoring window capture**: when the game is restored from minimized without taking focus, live detection resumes and no false "window lost" is reported.
- **VALORANT recordings treated as Apex**: whole-session finalizing and recovery keep the recorded game.
- **OBS per-match finalizing**: a failed live-event conversion still queues analysis and lists the output.
- **Live detection that did not finish cleanly**: match footage is kept instead of lost.
- **Recording stopping on some GPUs**: when the video processor cannot read a frame directly, it is copied first instead of ending the recording.
- **Dark cursor edges**: cursor shadows and edges are no longer drawn too dark.

**Analysis**
- **Battle Royale detected as Control**: fixes long stretches of a Battle Royale recording being treated as Control mode, which dropped every kill banner.
- **Stuck analysis queue or Studio**: the queue keeps moving when game detection fails or analysis is cancelled or fails, and Studio reloads or offers Retry.
- **Lost clips after reanalysis**: accepted AI clips are no longer lost when a run is cancelled, the cache location changes, or a game starts mid-run.
- **No analysis after an engine crash**: an internal engine error is reported instead of leaving the engine busy forever.

**Watch folders**
- **Files imported while still copying**: files are imported once the copy finishes and the file is unlocked; files whose permissions only allow reading are imported too.
- Watch-folder changes that cannot be saved now show a notice.

**Export**
- **Unneeded OpenH264 download prompt**: the export drawer waits for encoder detection before deciding whether OpenH264 is needed.
- **Fast export offered for mixed sources**: when a source's format cannot be read, export no longer offers stream copy.
- Multi-part export progress is weighted by each part's length, so it moves more evenly.

**Data safety**
- A corrupt settings file is kept, and privacy options (diagnostics, auto-recording) stay off.
- A library file that cannot be read or backed up is never overwritten.
- The storage location cannot be changed while unfinished recordings remain, so they are not stranded.

**Other**
- The live screen follows a new recording while it stays open, and the play button shows the right state after the video switches.
- Fixes a missing tray icon and errors caused by auto-update logging.

## How to update

- **0.2.2 through 0.3.6 installs** can upgrade through auto-update.
- **0.2.0/0.2.1 installs** need to download and run `Aditor-Setup-0.4.0.exe` manually.
- **Portable builds**: download `Aditor-0.4.0-Portable.exe` to update manually.

Windows executables are not code signed.
